# wshub

Локальный MCP-сервер (stdio), который даёт Claude Desktop доступ к папкам проектов по реестру
`~/.config/wshub/workspaces.toml`. Один сервер вместо отдельного filesystem-сервера на каждый проект.

Клиент не сообщает серверу, из какого проекта пришёл вызов, поэтому проект открывается явно:
`workspace_open(name)` возвращает хэндл `ws`, который передаётся первым аргументом во все остальные инструменты.

## Инструменты

| инструмент | что делает |
|---|---|
| `workspaces_list()` | проекты из реестра: имя, режим, описание |
| `workspace_open(name, mode="ro")` | хэндл, срок его жизни, политика и BRIEF проекта |
| `ls`, `tree`, `find`, `grep`, `read` | чтение; `grep` через ripgrep, если он есть в `PATH` |
| `extract` | текст из PDF, DOCX, XLSX (листы — в виде CSV) |
| `write`, `edit` | запись, только в режиме `rw`; `edit` заменяет ровно одно вхождение |
| `panel` | панель управления для человека (MCP Apps); в клиентах без Apps — текстовая сводка |

## Панель и `wshub doctor`

`panel` открывает в чате Claude Desktop панель: **Обзор** (проверки doctor, живые процессы сервера,
предупреждение «код новее запущенного»), **Проекты** (добавить, изменить, удалить; выбор папки, проверка BRIEF,
предпросмотр масок deny), **Сессии** (открытые хэндлы всех процессов, отзыв, запрет проекта и его снятие), **Журнал** (последние 500 записей
с фильтрами), **Копии** (сравнение с текущей версией и восстановление).

Менять реестр и состояние может только человек — через панель или руками:

- инструменты панели (`panel_*`) помечены `visibility: ["app"]`: хост не показывает их модели;
- каждое изменение дополнительно требует одноразовый код (10 минут), его выдаёт только `panel_data`,
  чтение (обход папок, журнал, копии) — ключ оттуда же.

Реестр из панели сохраняется через tomlkit (комментарии и порядок остаются), с проверкой до записи, атомарно;
прежняя версия — в `~/.local/state/wshub/registry-history/`. Остальные процессы подхватывают файл по mtime.

Desktop может держать несколько процессов wshub. Каждый пишет `~/.local/state/wshub/run/<pid>.json`
(старт, git HEAD кода, хэндлы без токенов, последний вызов); отзыв хэндла — файл `revoked`, его проверяют все процессы.
Флажок «Запретить открывать этот проект» в диалоге отзыва пишет проект в `blocked.json`: пока запрет не снят
на вкладке «Сессии», `workspace_open` и уже выданные хэндлы проекта отказывают во всех процессах.

Неизвестные разделы и ключи реестра (например, из более новой версии) сервер пропускает, а doctor и «Обзор»
показывают «неизвестный ключ <имя> — пропущен». Ошибка — только битый TOML и неверные значения известных ключей.

```bash
wshub doctor    # ripgrep, реестр, пути, запись в Desktop, процессы и отставание кода, размер журнала и копий
```

### Где Desktop берёт запись wshub (Windows)

Desktop из Microsoft Store (MSIX) читает конфиг не из `%APPDATA%\Claude\`, а из своей копии в пакете:
`%LOCALAPPDATA%\Packages\Claude_<id>\LocalCache\Roaming\Claude\claude_desktop_config.json`.
Перенаправление AppData действует только для процессов внутри пакета, поэтому из WSL, Проводника и `cmd`
виден классический `%APPDATA%\Claude\claude_desktop_config.json` — его MSIX-Desktop не читает.
`wshub doctor` показывает оба файла и помечает, какой читается.

## Установка

Нужны Python ≥ 3.10 и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/Sufir/wshub.git
uv tool install --editable ./wshub    # → ~/.local/bin/wshub
```

Claude Desktop (`claude_desktop_config.json`), Linux/macOS:

```json
"wshub": { "command": "/home/<user>/.local/bin/wshub" }
```

Windows + WSL:

```json
"wshub": { "command": "wsl.exe", "args": ["-d", "Ubuntu-22.04", "--", "/home/<user>/.local/bin/wshub"] }
```

Desktop держит конфиг в памяти и может перезаписать файл, пока запущен: правьте конфиг при закрытом Desktop.
Для Desktop из Microsoft Store файл лежит в пакете — см. «Где Desktop берёт запись wshub».

## Реестр

```toml
[defaults]
deny = [".env", ".env.*", "*.pem", "*.key", "id_rsa*", "id_ed25519*",
        "**/secrets/**", "**/node_modules/**", "**/.git/objects/**"]
max_read_kb = 512
ttl_hours = 8

[workspace.myproject]
path = "/home/<user>/myproject"
mode = "rw"                 # "ro" | "rw"
description = "Мой проект"
brief = ".agents/BRIEF.md"  # от корня проекта; отдаётся в workspace_open
deny = ["users*.csv"]       # добавляется к defaults.deny
```

Сервер перечитывает реестр при изменении — перезапуск не нужен. Модель реестр не меняет: правка — руками или в панели.
Ошибка в реестре блокирует все вызовы, пока её не исправят.

## Безопасность

- Пути проверяются через `resolve()` + `is_relative_to(корень)`; симлинки наружу, `../` и соседние папки с тем же префиксом отклоняются.
- Маски `deny` — без учёта регистра, по пути от корня и по имени, проверяются и запрошенный путь, и цель симлинка.
  `ls`/`find` имена показывают, `read`/`extract`/`write`/`edit` отказывают, `grep` такие файлы пропускает.
- Запись: не в `.git`, не через симлинк, атомарно (временный файл + `os.replace`) с сохранением прав.
  Перед изменением — копия в `~/.local/state/wshub/backup/<проект>/<время>/`.
- Журнал вызовов `~/.local/state/wshub/audit.jsonl` (sha256 до и после записи, без содержимого файлов).
- Сервер отказывается открыть проект, который содержит собственные каталоги wshub (код, реестр, состояние, установку).
- Недоступные по правам пути обходы пропускают и перечисляют в конце ответа.
