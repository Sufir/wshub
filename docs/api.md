# API хаба: доступ к моделям по ключу

## Назначение

Ядро `wshub.llm` — путь, которым хаб сам ходит к внешним моделям по ключу API: один запрос из терминала, оценка его
цены, учёт трат по зонам кредитов. Claude Code на подписке в этом журнале не учитывается; задачи wshub-code на
ключе (`billing = "key"`, `docs/code.md`, «Задачи на ключе») — учитываются, см. «Строки задач Code».

В пакете два провайдера: `anthropic` — Claude API (раздел «Провайдер anthropic») и фейковый `fake` (без сети,
детерминированный) — образец модуля и опора тестов. Ключ `~/.config/wshub/keys/anthropic` берут и задачи wshub-code на
ключе. Из чата ядро доступно через MCP-сервер `wshub-api` (раздел «Сервер wshub-api»).

**Без настроек реестра.** Достаточно ключа: `wshub api key set anthropic` — и `wshub api run`, и `wshub-api` работают.
`[api]` и `[workspace.<имя>.api]` по умолчанию включены, провайдер из словаря без своей секции берёт умолчания модуля
(без зон). Секции нужны только чтобы что-то переопределить или закрыть (раздел «Реестр»).

## Провайдеры

Ядро не знает форматов конкретного API. Провайдер — модуль в `src/wshub/llm/providers/`, который отдаёт
`create(conf) -> Provider`; `conf` — его секция `[api.providers.<имя>]` из реестра. Интерфейс (`llm/provider.py`):

| член | что делает |
|---|---|
| `name` | имя провайдера, как в словаре |
| `caps` | флаги из `batch`, `cache`, `schema`, `count_tokens`, `effort` |
| `models()` | уровень `cheap` / `standard` / `strong` → id модели |
| `price(model, usage)` | оценка в USD по таблице провайдера; неизвестная модель — `KeyError` |
| `estimate(request, key=None)` | оценка входа: точная при `count_tokens` (ядро передаёт ключ, если он есть), иначе символы / 4 |
| `run(request, key)` | один запрос; модель уже выбрана ядром |
| `batch_submit` / `batch_status` / `batch_results` / `batch_cancel` | пакеты (только при `batch` в `caps`), раздел «Пакеты» |

Запрос и ответ — нейтральные типы `Request`, `Usage`, `Response` (`llm/types.py`): провайдер сводит к ним свои поля.
Чего у провайдера нет в `caps` (схема ответа, effort, кэш), ядро отклоняет до запроса.

**Как добавить провайдера:**

1. Модуль `src/wshub/llm/providers/<имя>.py` с `create(conf)`.
2. Одна строка в словаре `PROVIDERS` в `src/wshub/llm/providers/__init__.py`.
3. Ключ `wshub api key set <имя>` — провайдер доступен по нему и без секции (умолчания модуля). Секция
   `[api.providers.<имя>]` в реестре — для переопределений; с секцией провайдер доступен и без ключа (оценка грубая,
   запрос — отказ «ключа нет»).

Кода извне пакета хаб не загружает: провайдер — только из словаря в коде.

## Провайдер anthropic

Claude API напрямую: `POST https://api.anthropic.com/v1/messages`, заголовки `x-api-key`, `anthropic-version:
2023-06-01`, `content-type: application/json`. HTTP — только стандартная библиотека Python.

- **Уровни:** `cheap` — `claude-haiku-5-5`, `standard` — `claude-sonnet-5-5`, `strong` — `claude-opus-5-5`;
  переопределяются `models` в `[api.providers.anthropic]`.
- **`caps`:** `batch`, `cache`, `schema`, `count_tokens`, `effort`. Пакеты — раздел «Пакеты».
- **Кэш:** `system` уходит одним блоком; подсказка `cache` запроса: `none` — без `cache_control`, `short` —
  `{"type": "ephemeral"}` (5 минут), `long` — `{"type": "ephemeral", "ttl": "1h"}`. Пустой `system` не отправляется.
- **Схема ответа:** `--schema` → `output_config.format = {"type": "json_schema", "schema": …}`; ответ — JSON в
  текстовом блоке, хаб разбирает его. Не разобрался — отказ с первыми 200 символами текста. Запрос при этом уже
  оплачен: строка журнала (`ok: false`) — с фактической стоимостью по `usage` ответа, а не $0. То же для любой ошибки
  разбора после успешного HTTP-ответа (ответ не JSON-объект, `usage` не разобран) — там стоимость по оценке до запроса.
- **Effort:** `--effort` → `output_config.effort` (`low`, `medium`, `high`, `xhigh`, `max`).
- **Оценка входа:** если ключ есть, `POST /v1/messages/count_tokens` (бесплатно) с тем же телом без `max_tokens` —
  точно. Ключа нет — символы / 4, `--estimate` пишет «(грубо)». Сбой `count_tokens` — отказ до запроса.
- **Ответ:** текст — из текстовых блоков; `usage` → `input`, `output`, `cache_read`, `cache_write` (вся запись в
  кэш), `cache_write_1h` (её часть с TTL 1 ч); модель — фактическая, из ответа.
- **Ошибки:** HTTP-ошибка — отказ `HTTP <код> <error.type>: <error.message>` и `(request-id …)` для поддержки.
  429 и 529 — один повтор после `retry-after` (не больше 60 с; нет заголовка — через 1 с), затем отказ; остальные —
  без повторов. Таймаут соединения и ответа — `timeout_s` (по умолчанию 300 с). Редиректы не выполняются: ключ не
  уходит по чужому адресу.
- **Ключ** — только в заголовке запроса: ни он, ни заголовки запроса не попадают в тексты ошибок и журнал.
- **`base_url`** — адрес API (по умолчанию `https://api.anthropic.com`): только `https://`; `http://` — лишь для
  `127.0.0.1` и `localhost` (тесты).

**Цены** — $ за 1 млн токенов, сверка с platform.claude.com/docs/en/about-claude/pricing 2026-10-20:

| модель | вход | выход | запись кэша 5 мин | запись кэша 1 ч | чтение кэша |
|---|---|---|---|---|---|
| `claude-opus-5-5` | 4 | 20 | 5 | 8 | 0.20 |
| `claude-sonnet-5-5` | 2 | 10 | 2.50 | 4 | 0.10 |
| `claude-haiku-5-5`, промпт ≤ 100 000 | 0.10 | 0.50 | 0.125 | 0.20 | 0.01 |
| `claude-haiku-5-5`, промпт > 100 000 | 0.50 | 2.50 | 0.625 | 1 | 0.05 |

Промпт для порога Haiku — `input + cache_write + cache_read`. Запись в кэш считается по цене 5 минут, кроме части,
которую ответ отнёс к TTL 1 ч (`usage.cache_creation.ephemeral_1h_input_tokens`). Модель вне таблицы — отказ «цена
модели … неизвестна».

## Ключи

```sh
wshub api key set <провайдер>     # скрытый ввод (getpass), пустой — отказ
wshub api key check <провайдер>   # «ключ есть, права верны» или что не так; значение не выводится
```

- Файл `~/.config/wshub/keys/<провайдер>`: каталог `keys` — 0700, файл — 0600, владелец — текущий пользователь.
  Иначе — отказ с командой исправления: `права ключа <путь> — <факт>; исправь: chmod 600 <путь>`. Симлинк — отказ.
- Запись атомарная: временный файл сразу создаётся с правами 0600, затем переименовывается на место.
- Ключ читается только в момент запроса. В журнал, ответ, вывод и тексты ошибок он не попадает: если провайдер
  вернул ошибку с ключом в тексте, ядро заменяет на `<ключ скрыт>` и сам ключ, и любой его кусок от 8 символов.
- Без терминала `key set` отказывает: скрытый ввод там невозможен.
- `~/.config/wshub` уже закрыт для задач Claude Code (`deny_read`) и для файлового сервера (служебные данные).

## Деньги — всё опционально

**Принцип: без явной настройки оператора ничего не ограничивает и не предупреждает** — каждая настройка ниже по
умолчанию выключена. Действуют они на всё, что тратит по ключу: `wshub api run`, сервер `wshub-api`, пакеты, задачи
wshub-code на ключе. Журнал трат пишется всегда.

| настройка | по умолчанию | что делает | пример |
|---|---|---|---|
| `[api] max_usd_per_call` | выключено | отказ до запроса, если оценка одного запроса (у пакета — каждого запроса) выше потолка; к задачам Code не применяется | `max_usd_per_call = 1.0` |
| `[api] daily_usd` | выключено | отказ, если с тратами текущих суток (все провайдеры и задачи Code на ключе, местное время) оценка превысит потолок | `daily_usd = 10.0` |
| `[api.providers.<имя>] included_usd` + `credits_until` | выключено | включает зоны: запрос (пакет, задача Code) должен поместиться в остаток включённой зоны или разрешения `allow` | `included_usd = 100`, `credits_until = "2026-10-23"` |
| `wshub api credits <имя> --left USD --until ДД.ММ` | выключено | то же, что `included_usd`, командой: остаток из консоли провайдера, новый цикл | `wshub api credits anthropic --left 37.5 --until 23.10` |
| `wshub api allow <имя> --usd USD --until ДД.ММ` | выключено | разрешает тратить купленную зону на сумму до срока; без него купленная — никогда | `wshub api allow anthropic --usd 20 --until 31.10` |
| `[api.warn] day_usd` | выключено | `⚠`, когда траты за сутки (все провайдеры, задачи Code на ключе тоже) выше порога | `day_usd = 5` |
| `[api.warn] left_usd` | выключено | `⚠`, когда остаток включённой зоны ниже порога — только если зона включена | `left_usd = 10` |
| `[api.warn] call_usd` | выключено | `⚠`, когда оценка одного запроса или пакета выше порога; запрос **не** останавливается (это не `max_usd_per_call`) | `call_usd = 0.5` |
| `[workspace.<имя>.code] max_budget_usd` | выключено | бюджет задачи Code (`--max-budget-usd` claude); на ключе при включённой зоне без него бюджет — остаток зоны | `max_budget_usd = 20` |

- Без зон строки журнала идут во включённую зону, `run --estimate` пишет «зоны не проверяются», `stats` — то же
  вместо остатков.
- **Предупреждения** `[api.warn]` только показывают: строка `⚠ …` в выводе `wshub api run|stats|batch …` (и
  `--estimate`), в ответах инструментов `wshub-api`, в строке оплаты задачи Code на ключе (`code_status`,
  `code_result`) и в `wshub doctor`. Ничего не останавливают.
- **Журнал трат не читается** (файл не читается целиком или не разбирается ни одна строка): если в реестре нет ни
  `max_usd_per_call`, ни `daily_usd`, ни `included_usd` провайдера — проверять нечего, запрос и задача Code идут без
  проверок со строкой `⚠ журнал трат не читается: …`. Задана хоть одна из них — отказ: проверить её нечем.
- **Строка журнала не записалась** после оплаченного ответа (диск, права) — ответ отдаётся, ошибка — строкой
  `⚠ журнал трат: строка не записана (…) — сумма не учтена` (CLI и сервер). У `batch results` — так же; следующий
  `results` допишет недостающие строки.
- `wshub doctor` (строка «wshub-api») показывает включённое одной строкой — `деньги: max_usd_per_call $1.00 ·
  daily_usd $10.00 · зоны: anthropic (credits) · allow: anthropic $20.00 до 31.10 · max_budget_usd (Code): payload $20
  · [api.warn] day_usd $5.00` — или `деньги: ограничений нет`; предупреждения `[api.warn]` — строками `⚠`.

## Зоны и цикл

Траты провайдера делятся на две зоны:

- **включённая** — `included_usd` до `credits_until` из реестра или из последней команды `credits` (команда
  сильнее реестра). Тратится без отдельного разрешения;
- **купленная** — только при действующем разрешении `allow` (сумма и срок). Нет разрешения — отказ до запроса:
  «включённые кредиты исчерпаны (≈$X); купленные — только по разрешению оператора: wshub api allow …».

**Цикл** — от последней команды `credits` (или от начала журнала) до `credits_until`. После `credits_until`
включённая зона считается нулевой, пока оператор не введёт новый остаток.

**Проверка до запроса:** оценка = `estimate` входа + `max_tokens` выхода по цене модели. При `cache = short | long`
системная часть входа (символы / 4, не больше всего входа) оценивается по цене записи в кэш соответствующего TTL
(5 мин или 1 ч), остальной вход — по цене входа. Отказ, если оценка выше
`max_usd_per_call`, если с тратами текущих суток (все провайдеры, местное время) она превышает `daily_usd`, или
если она не помещается ни в остаток включённой зоны, ни в остаток разрешения на купленную — каждое из трёх, только
если задано (раздел «Деньги»). Перед отправкой проверка
повторяется под блокировкой журнала (`ledger.lock`), и блокировка держится до записи строки: параллельные запросы
идут по очереди и не тратят один и тот же остаток, а `revoke` действует и на уже проверенный запрос.

**«Сгорит»:** до `credits_until` меньше 7 дней, а включённый остаток больше $10 — `run` и `stats` говорят об этом
строкой `⚠ сгорит: …`.

**Журнал** — `~/.local/state/wshub/api/ledger.jsonl`, строка JSON на запрос (время, провайдер, модель, уровень,
проект, шаблон, `usage`, `cost_usd`, зона, `ok` или ошибка) и на команды `credits`, `allow`, `revoke`.
Нечитаемая строка (оборванная запись) пропускается, `run` и `stats` пишут «журнал: пропущено строк N». Отказ — только
если файл не читается целиком или при ненулевом размере не разбирается ни одна строка.

**Строки задач Code.** Задача wshub-code на ключе проверяет только то, что оператор включил явно: `daily_usd`
— если ключ есть в `[api]`, зоны — если в `[api.providers.anthropic]` задан `included_usd` **или** введена команда
`wshub api credits anthropic`; `max_usd_per_call` к ней не применяется. При такой проверке звено пишет на старте
**резерв** — строку `kind = "run"` с `provider = "anthropic"`, `template = "code"`, `project`, `model`, `zone`, `job`
(id звена), `cost_usd` = бюджет звена и `reserve: true`; проверка и запись идут под той же блокировкой `ledger.lock`.
Без бюджета звена при включённой зоне бюджет — остаток зоны (или разрешения `allow`) вниз до цента: он же резерв и
флаг `--max-budget-usd` claude, так что параллельная задача на той же зоне до итога первой не стартует; без зоны
(проверка только дня) резерв — 0. По итогу звена дописывается строка того же `job` с фактом (`cost_usd` — стоимость
звена, `reserve: false`, `ok`) — всегда, даже без проверок (зона тогда — включённая). **Из строк одного `job`
действует последняя**: зоны, `daily_usd` и `stats` считают её одну. Отказ ключа (`key_rejected`) — факт $0. Отмена
или таймаут без итога — оценка по последнему `total_cost_usd` в потоке событий, если он был, с пометкой `note =
"оценка, итога нет"`; не было — резерв остаётся, как у звена без итога (`lost`).

**Резерв пакетов.** При денежной проверке (`max_usd_per_call`, `daily_usd` или зоны провайдера) `batch submit` пишет
под `ledger.lock` строку `kind = "run"` с `batch` (id), `reserve: true` и `cost_usd` = оценка пакета: следующий пакет
и запрос видят её в зонах и потолке дня. Строки `results` этого пакета её заменяют — резерв действует, пока у пакета
нет ни одной строки факта. Без проверок резерва нет.

## Реестр

Всё в этом разделе необязательно: без секций API включён, провайдер работает по ключу с умолчаниями модуля.

```toml
[api]
# enabled = true           # общий выключатель API хаба; по умолчанию включён, false — выключить целиком
# max_usd_per_call = 1.0   # потолок оценки одного запроса; не задан — потолка нет
# daily_usd = 10.0         # потолок трат за сутки, все провайдеры; не задан — потолка нет

[api.warn]                 # пороги предупреждений «⚠» — только показ; каждый не задан — порога нет
# day_usd = 5              # траты за сутки выше
# left_usd = 10            # остаток включённой зоны ниже (только при включённой зоне)
# call_usd = 0.5           # оценка одного запроса или пакета выше

[api.providers.anthropic]  # секция провайдера — только для переопределений; имя — из словаря (fake, anthropic)
# included_usd = 100       # включает зоны; при included_usd > 0 нужен credits_until
# credits_until = "2026-10-23"
# models = { cheap = "…", standard = "…", strong = "…" }   # переопределение уровней
# strong_requires_choice = true                            # strong — только с --choice operator
# timeout_s = 300          # таймаут соединения и ответа, с
# base_url = "https://api.anthropic.com"                   # только https; http — для 127.0.0.1/localhost

[workspace.payload.api]
enabled = false            # закрыть проект от отправки файлов в API; по умолчанию — открыт (true)
```

- Провайдер без своей секции доступен, если его ключ есть и права верны: умолчания модуля, зон нет (их включит команда
  `credits`), `strong_requires_choice = true`. Нет ни секции, ни годного ключа — отказ «нет секции … и нет годного
  ключа (…)».
- Проект открыт для отправки файлов в API по умолчанию — так же, как задачи wshub-code на ключе отправляют его файлы.
  Deny-маски проекта действуют всегда.

- Ошибка в `[api]` или `[api.providers.*]` ломает только API хаба (как `[code]` — только `wshub-code`); ошибка в
  `[workspace.<имя>.api]` — только этот проект. Файловый сервер и `wshub-code` работают.
- Неизвестный провайдер в `[api.providers]` и неизвестные ключи — предупреждение, секция пропускается.
- `strong_requires_choice` по умолчанию `true`: уровень `strong` и любая модель, совпадающая со strong-моделью
  реестра или собственной strong-моделью провайдера (как `--model`, так и через переопределение другого уровня), —
  только с `--choice operator`.
- Явная `--model`, которой нет среди моделей уровней (с учётом переопределений), — только с `--choice operator`,
  независимо от `strong_requires_choice`. Текст отказа называет уровни и их модели.

## CLI

```sh
wshub api key set <провайдер>
wshub api key check <провайдер>
wshub api run --provider P --project X (--tier T | --model M) [--system FILE] --input FILE [--schema FILE]
              [--max-tokens N] [--effort E] [--choice operator] [--estimate] [--out FILE]
wshub api batch submit|status|results|cancel …     # раздел «Пакеты»
wshub api stats [--days N]
wshub api credits <провайдер> --left USD --until ДД.ММ[.ГГГГ]
wshub api allow <провайдер> --usd USD --until ДД.ММ[.ГГГГ]
wshub api allow <провайдер> --revoke
```

- `run` выводит ответ и строку `API: <модель> · вход N (из кэша M) · выход K · ≈$X · цикл ≈$Y из $Z, до ДД.ММ`
  (часть «цикл» — только при проверяемых зонах). `--max-tokens` по умолчанию 1024. `--estimate` — оценка цены и
  зона без запроса к модели; ключа нет — без ключа, оценка входа грубая; ключ есть и у провайдера `count_tokens` —
  точная.
- `[api] enabled = false` или проект с `[workspace.<имя>.api] enabled = false` — отказ до чтения файлов.
- `--input`, `--system`, `--schema` читаются по политике проекта: путь внутри корня (относительный — от корня проекта),
  симлинк наружу и deny-маски — отказ, размер — не больше `max_read_kb`.
- Ответ длиннее 8 КБ — в `--out` или в `~/.local/state/wshub/api/out/`, на экран — путь. С `--out` ответ всегда
  пишется в файл.
- `stats` — траты за цикл (или за `--days N`) по провайдерам (с секцией или с ключом), зонам, моделям и проектам,
  разрешение на купленную зону, строка «сгорит».
- `credits` вводит остаток включённых кредитов (из консоли провайдера) и начинает новый цикл; `allow` разрешает
  купленную зону на сумму до срока, новое разрешение заменяет прежнее; `--revoke` снимает разрешение.
- Дата `ДД.ММ` без года — ближайшая будущая (сегодня включительно); срок действует весь указанный день.

## Сервер wshub-api

MCP-сервер (stdio) для чата Claude: дешёвая модель по ключу хаба делает объёмную однотипную работу — классификацию,
извлечение, сводки по файлам проекта; ответ возвращается в чат или пишется файлом в проект. Всё идёт через то же ядро:
те же барьеры, оценка, зоны и журнал трат, что у `wshub api run`. Отдельный сервер, как `wshub-code`: его выключают в
Desktop, не трогая доступ к файлам.

**Установка.** `wshub setup --api` добавляет запись `wshub-api` (`wshub api` без аргументов) в конфиги Claude Desktop
рядом с `wshub`; `wshub uninstall` её снимает. Затем — перезапуск Desktop и ключ `wshub api key set anthropic`;
реестр трогать не нужно (раздел «Без настроек реестра» в начале). `wshub doctor` — строка «wshub-api»: запись в
Desktop, `[api]`, закрытые проекты, ключи провайдеров (без значения).

**Инструменты:**

| инструмент | что делает |
|---|---|
| `api_models()` | провайдеры (с секцией или с ключом): уровни → модели, `caps`, `strong_requires_choice`, есть ли ключ |
| `api_run(project, …)` | один запрос; ответ — текст или JSON по схеме, строка `API: …`, предупреждения |
| `api_estimate(project, …)` | те же входы, что у `api_run` (без `out_file`), — оценка без запроса к модели |
| `api_stats(days=None)` | как `wshub api stats` |
| `api_batch_submit(project, …)` | пакет запросов, раздел «Пакеты» |
| `api_batch_status(id="")` | состояние пакета; без `id` — список |
| `api_batch_results(id)` | ответы законченного пакета — файлами; в чат — сводка и пути |
| `api_batch_cancel(id)` | отмена пакета |

Параметры `api_run`:

- `project` — имя проекта реестра;
- вход — `input` (текст) **или** `input_file` (путь в проекте); так же `system` / `system_file`, `schema`
  (JSON-объект схемы) / `schema_file`. Файлы — по политике проекта, как в CLI;
- `provider` — по умолчанию единственный доступный, иначе обязателен; `tier` (`cheap` | `standard` | `strong`) или
  `model`; `effort`; `max_tokens` (по умолчанию 1024); `cache` (`none` | `short` | `long`);
- `choice="operator"` — только когда выбор сделал оператор: снимает запрет ядра на strong и модель вне уровней, как
  `--choice operator`; `reason` — обязателен (≥ 15 символов) для strong и модели вне уровней, в том числе при
  `choice="operator"`;
- `out_file` — путь в проекте, куда записать ответ.

Ответ длиннее 8 КБ без `out_file` пишется в `~/.local/state/wshub/api/out/`, в чат — путь и первые 2 КБ.

**Пример вызова** (из чата):

```
api_run(project="payload", input_file="docs/notes.md", system="Сводка в 5 пунктах", tier="cheap")
api_run(project="payload", input_file="data/review-17.txt", schema={"type": "object", "properties":
        {"label": {"type": "string"}}}, tier="cheap", out_file="out/review-17.json")
```

**Защита:**

- **Блокировка из панели** — проект, заблокированный пользователем, недоступен: проверка в начале каждого вызова
  `api_run` / `api_estimate` (до чтения файлов) и ещё раз перед записью `out_file`.
- **`out_file`** — только в проекте `rw` (`ro` — отказ); путь внутри корня, симлинк в конце и каталоги-симлинки наружу
  — отказ; не под deny-масками, не в `.git`, не в служебных каталогах хаба. **Существующий файл не перезаписывается**
  (отказ до запроса). Перед записью проверка повторяется по свежему реестру и файлам: за время запроса проект мог
  стать `ro`, каталог — симлинком наружу, файл — появиться. Запись атомарная (временный файл в том же каталоге, затем
  `link`), права 0644; файловой системе нужны жёсткие ссылки. Если записать не удалось уже после оплаченного запроса —
  ответ сохраняется в `~/.local/state/wshub/api/out/`, в чат — путь и причина, текст ответа в чат не идёт.
- **Ключ** не попадает в ответы инструментов, журнал вызовов, журнал трат и тексты ошибок.
- **Журнал вызовов** — `~/.local/state/wshub/audit.jsonl`, как у `wshub-code`: строка на вызов — инструмент, проект,
  провайдер, модель, сумма (и у оплаченного вызова, ответ которого не разобрался); без текстов входа и ответа (в том
  числе без начала битого JSON-ответа).

`api_estimate` пишет вход целиком; при `cache = short | long` в скобках — его часть, оцененная по цене записи в кэш:
`вход ≈102 (запись в кэш 100)`.

## Пакеты

Batch API провайдера (`caps` `batch`; сейчас — `anthropic`): много запросов одним пакетом **вдвое дешевле** — −50 % ко
входу и выходу (pricing, 2026-10-20). Скидку к записи и чтению кэша хаб тоже считает −50 % — это допущение PoC WSH-4.0,
отдельно не сверено. Расплата — время: пакет обрабатывается **до 24 ч** (в PoC три коротких запроса — 4 минуты).

**Когда выгодно:** много однотипных запросов (классификация, извлечение полей, сводки по десяткам файлов), ответ не
нужен сразу. Один срочный вопрос — `run` / `api_run`.

**Кэш общего `system`:** с `--cache long` (`cache="long"`) `system` уходит с `cache_control` на 1 час; первый запрос
пакета сам записывает его в кэш, остальные читают. Отдельный прогрев не нужен (в PoC прогрев без схемы ответа пакет со
схемой не покрыл).

```sh
wshub api batch submit --provider anthropic --project payload --tier cheap --system prompts/classify.md \
    --inputs-glob 'reviews/*.txt' --schema schemas/label.json --cache long --out-dir out/labels
wshub api batch status msgbatch_01…       # in_progress → ended; без ID — список пакетов
wshub api batch results msgbatch_01…      # ответы в out/labels/<имя входа>.json, сводка, траты
wshub api batch cancel msgbatch_01…
```

Из чата:

```
api_batch_submit(project="payload", inputs_glob="reviews/*.txt", system_file="prompts/classify.md", tier="cheap",
                 schema_file="schemas/label.json", cache="long", out_dir="out/labels")
api_batch_status(id="msgbatch_01…")
api_batch_results(id="msgbatch_01…")
```

- **Вход** — один запрос на вход, до 1000 в пакете (больше — отказ). CLI: `--inputs ФАЙЛ…` (значения до следующего
  `--…`) или `--inputs-glob 'МАСКА'` (как `find`: без `/` — по имени, с `/` — по пути от корня; deny, `.git`,
  симлинки и не обычные файлы пропускаются). Сервер: `input_files` (список путей), `inputs_glob` или `inputs` (список текстов) — ровно одно.
  Файлы — по политике проекта, как `--input`. Остальные параметры — как у `run` / `api_run`, `--cache none|short|long`.
- **`custom_id`** — по имени входа без расширения: латиница, цифры, `_`, `-` (прочее — `_`), до 64 символов; дубли —
  `-2`, `-3`; без латиницы и цифр (и у текстов) — `r<номер>`. Файл ответа — имя входа без расширения (кириллица
  сохраняется) + `.json` при схеме, иначе `.md`. Результаты провайдер отдаёт в своём порядке — хаб раскладывает их
  только по `custom_id`.
- **Проверки до отправки** — для каждого запроса те же, что у `run`: барьеры реестра, выбор модели, strong и модель
  вне уровней — только `--choice operator` (из чата — ещё и `reason`). Деньги — только заданные оператором: оценка
  каждого запроса — со скидкой; `max_usd_per_call` — на каждый запрос, `daily_usd` и зоны — на сумму пакета, заново
  под `ledger.lock` перед отправкой. Точная оценка входа (`count_tokens` на каждый запрос) — только если задана хоть
  одна денежная проверка; иначе вход — грубо (символы / 4), без запросов к провайдеру. При денежной проверке
  `submit` пишет резерв на оценку пакета, `results` заменяют его фактом (раздел «Зоны и цикл»); без проверок резерва
  нет. Ответа на создание пакета нет за таймаут — отказ с текстом «пакет мог создаться у провайдера — проверь
  `wshub api batch status` или консоль, прежде чем повторять».
- **`--out-dir` / `out_dir`** — каталог в проекте с теми же проверками, что `out_file` (только `rw`, не `.git`, не под
  deny, не наружу, не существующий файл); файл ответа, который уже есть, — отказ до отправки. Без него ответы — в
  `~/.local/state/wshub/api/out/<id>/`.
- **Учёт** — `~/.local/state/wshub/api/batches/<id>.json` (0600): провайдер, проект, модель, число запросов,
  `custom_id` → вход (путь или первые 80 символов текста), имя файла ответа и оценка, время, состояние, `out_dir`, зона.
  Ключа там нет. `status` без ID — список пакетов учёта; незаконченные хаб переспрашивает у провайдера.
- **`results`** — только у законченного пакета (`ended`), иначе отказ со счётчиками. Успешные ответы — файлами, без
  перезаписи: перед записью проверка `out_dir` повторяется (сервер — и блокировку из панели); файл с тем же ответом —
  «записан ранее», с другим или запись не прошла — ответ в `~/.local/state/wshub/api/out/<id>/`. Сводка: успешно,
  с ошибкой (по `custom_id` с причиной), сумма со скидкой. Результат с `custom_id` не из учёта пакета или повтор —
  в сводке как ошибка, без файла и строки журнала. В чат — сводка и пути; тексты — только если ответов ≤ 5 и каждый
  ≤ 2 КБ и проект не заблокирован.
- **Журнал трат** — строка на каждый результат: `batch` (id) и `custom_id` вместо `template`, `usage`, `cost_usd` со
  скидкой, зона — та, что определена при отправке. `errored` / `canceled` / `expired` — `ok: false`, $0 (не оплачены).
  Ответ получен, но JSON по схеме не разобран — `ok: false`, цена по `usage`, файла нет; `usage` не разобран или его
  нет — по оценке запроса из учёта. **Повторный `results` строк не дублирует:** пишутся только `custom_id`, которых в журнале у этого
  пакета ещё нет (под `ledger.lock`). Строки ложатся в сутки выборки результатов.
- **`cancel`** — отмена у провайдера; уже выполненные запросы оплачены, их ответы — через `results`.
- `[api] enabled = false` и закрытый проект запрещают отправку (`submit`); `status`, `results`, `cancel` работают —
  данные уже у провайдера. Ключ — только в заголовке: ни в учёте, ни в выводе, ни в журналах; ID пакета — только
  `[A-Za-z0-9_-]`. Результаты хаб берёт по адресу `base_url`, а не по `results_url` ответа.

## Что ядро гарантирует и чего нет

Гарантирует:

- до запроса проверены выключатели реестра, `caps` провайдера, выбор сильной модели и модели вне уровней, заданные
  оператором потолки и зоны;
- купленная зона не тратится без действующего разрешения оператора;
- ключ не попадает в вывод, журнал и тексты ошибок; права ключа проверяются при каждом чтении;
- файлы проекта читаются только по его политике.

Не гарантирует:

- **точность сумм.** Все суммы — оценка хаба по таблице цен провайдера (поэтому «≈», округление до цента), а не
  списание у провайдера. Фактическая цена ответа может немного превысить остаток зоны, проверенный по оценке.
  Сверка — команда `credits` по остатку из консоли провайдера, когда оператор сочтёт нужным;
- учёт трат вне хаба (консоль провайдера, другие программы с тем же ключом);
- строку журнала при аварийном обрыве процесса посреди запроса.
